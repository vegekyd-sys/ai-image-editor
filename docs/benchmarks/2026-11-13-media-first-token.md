## 改动

- DeepSeek 的站内原图以原始字节随首个模型请求传入，不缩图、不重编码、不改 detail，不降 thinking。其余供应商保持原路径。仅允许明确的自有 Storage origin/path，拒绝重定向；单图 8MiB、单批 16MiB、最多八个唯一对象、两秒下载预算。超限或失败继续使用原 URL，媒体不会被丢弃。内部 request 标记避免失败后在 Agent 入口再下载一遍。
- 图片字节准备和视频理解在 snapshots 读完后立即启动，与历史、音轨、草稿等上下文查询重叠；进入规划前仍等待所有必要视觉证据。GUI 显式原图与同一上下文图匹配时复用准备结果；标注、草稿等瞬时图保留自己的输入。
- 视频首轮仍调用现有 Gemini 3.8/low，全片、音轨、时间轴合同不变。摘要显式要求在原本会截到 900 字符的证据预算内覆盖每个场景，保留开头和结尾，减少生成后被裁掉的信息。详细 `analyze_video`、`preview_frame` 工具完整保留。

DeepSeek 支持 URL 与 base64 两种输入；当前官方请求体上限为 48MiB。本候选使用更小的内联预算，为工具和文本留余量；没有把 detail 改成 low。[官方 Vision 文档](https://api-docs.deepseek.com/guides/vision/)

## Google 与质量观察

Google 在较早本机实验出现 Files 上传约 106 秒中止，另有一次 CDN fetch 失败，均保留为异常。随后独立真实视频复查成功：约 9.8MB inline 18.05 秒；约 25MB Files 33.33 秒，返回描述覆盖开头和片尾标题。这证明当时两条路径可用，不代表长期无故障。

已查看源图和视频代表帧，检查两版回复。图片主体、岩壁光影、瀑布等主要细节可对应原图；视频开头、舞台表演、中文片尾标题也能对应。但候选有把六个毛线角色说成七个的回复，基线也有末镜景别不准确等表述。没有将性能收益当成理解质量胜出或完整不退化验收。首字指标包含模型自然生成的“先检查结尾”等动作预告；整轮结束另表报告。

这只是一个图片和一个视频家族的新项目分析/策划测试；未测试长历史、多图批量、大量长视频、网页点击到 DOM、iOS 真机或完整媒体创作质量。没有调用图片、视频或音乐生成。
