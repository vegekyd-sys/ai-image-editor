# 工作区目录查询失败保护

2026-11-15 线上监控在 `/api/skills` 和 `/api/agent/run` 捕获 workspace list 的 `canceling statement due to statement timeout`。Vercel 请求仍为 HTTP 200；完整 request logs 中才能看见工作区列表错误，Agent 代表消息并非实际错误正文。

此前 `dbListFiles` 在查询失败时记录错误并返回空数组。调用方无法区分“确实没有文件”与“数据库未返回目录”，会继续拼接内置技能、计算目录版本并缓存结果。技能安装的同名检查也可能在缺少目录时继续。客户端还可能把 `/api/skills` 的错误响应体写入原生缓存，覆盖最后一次有效列表。

候选改动：

- 工作区列表读取最多两次，间隔 250ms；只重试 statement timeout 和网络等瞬时错误，重建相同 owner/global 和路径条件，不扩大读取范围。
- 持续失败抛出 `WorkspaceListUnavailableError`，不把缺失目录当空列表，不缓存残缺索引。API 走既有错误响应，Agent 技能发现不静默缺省；需要目录检查的安装在写入前停止。
- `/api/skills` 原生缓存只接收含 skills 数组的有效结构。错误体不会覆盖上次有效目录，旧的无效缓存会清除；真正的空数组仍有效，其它资源缓存合同不变。

这是一层恢复及数据完整性保护，不证明数据库慢查询、锁或资源争用已经解决。只补一次读取，避免持续失败时无限增加数据库压力；不修改 SQL、索引、RLS、数据库配置或既有用户数据。当前无直连诊断凭据，未取得执行计划、锁及 CPU 的现场证据。

39 项定向回归覆盖超时恢复、权限错误不重试、重试上限、查询范围、缓存不污染、阻止安装写入、轻量技能索引、workspace mirror 和原生页面；全项目 TypeScript 检查通过。CLI/npm、Skill 正文和模型默认值没有变化。候选尚未合入 dev 或发布生产。
