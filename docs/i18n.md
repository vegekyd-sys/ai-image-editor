# Makaron i18n

Makaron currently supports four product locales:

| Locale | Browser aliases | AI output language |
| --- | --- | --- |
| `zh` | `zh-CN`, `zh-SG`, `zh-Hans` | Simplified Chinese |
| `zh-Hant` | `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant` | Traditional Chinese |
| `ja` | `ja`, `ja-JP` | Japanese |
| `en` | `en`, `en-US`, `en-GB` | English |

## Source of truth

- `src/lib/locales/index.ts` is the locale registry. It owns supported codes, aliases, browser detection, content fallbacks, typed translation lookup, and AI language instructions.
- `src/lib/locales/zh.ts` defines the translation schema. Every other locale must satisfy the same keys and formatter signatures.
- `src/lib/i18n.tsx` is the client provider. It receives the server-negotiated initial locale, persists the selection to local storage and the `locale` cookie, updates the document language, and renders the shared selector.
- `src/lib/server-locale.ts` applies the same normalization to cookies and `Accept-Language` for the root layout and API routes.
- `src/proxy.ts` normalizes `?locale=` aliases into the request/response cookie before rendering, so shared links such as `?locale=ja-JP` do not flash the default language.

Product UI should call `t('domain.key')`. Do not add `locale === 'zh' ? ... : ...` branches. Server and model code should use `translate`, `getReplyLanguageInstruction`, or `getOutputLanguageRequirement` from the registry.

Database-backed labels should use `pickLocalizedValue`. Traditional Chinese falls back through `zh-Hant → zh → en`; Japanese falls back through `ja → en`.

## Model output rules

- Keep general prompt framing and automatic image-analysis prompts in English, then append the locale instruction. A Chinese base prompt can overpower a Japanese or English reply instruction.
- Tips must prepend `getTipsLanguageInstruction(locale)` to both the system and user messages. Google structured output must also put the concrete language in each `label` and `desc` schema description.
- Keep `editPrompt` in English regardless of the UI locale. Only user-facing `label` and `desc` fields are localized.
- Japanese instructions explicitly require natural kana and forbid Chinese output. Traditional Chinese instructions require Traditional characters and forbid Simplified Chinese.

## Adding a locale

1. Add one entry to `LOCALE_CONFIG`, including browser aliases and fallbacks.
2. Add a complete dictionary under `src/lib/locales/` and register it in `translations`.
3. Add locale-specific Tips JSON formatting and verify the system, user, and structured-schema instructions all name the new output language.
4. Run `npx vitest run __tests__/i18n.test.ts`, `npx tsc --noEmit`, and `npm run build`.

The i18n test enforces exact key parity and checks normalization, formatter behavior, database-label fallback, and AI output-language alignment.
