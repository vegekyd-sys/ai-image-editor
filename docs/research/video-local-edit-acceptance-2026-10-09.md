# 局部编辑验收合同（2026-10-09）

验收走新项目的 `makaron chat`，使用自然语言原始需求；GUI 选区不是前提。
同一套 Agent/工具合同处理全部场景，不手写某条视频专用的供应商 prompt，
不手工修补验收成片。模型失败可改用 Seedance 2.5 Eco，保留失败版本。

## 两类意图

- `modify`：在原序列内部修改内容。首尾构图、动作状态和进出连接保留；
  中间必须显著满足需求。相机变化、多视角或分层表达本身不等于整段替换。
- `replace`：用户明确丢弃整段镜头或改换整个场景/动作/构图。
  保留用户要求的人物等属性，但不要求恢复原镜头首尾，不据此判失败。

时间范围前缀“把 X–Y 秒换成”不能单独决定类型。
用户明确要求修正的错误不是需要保留的属性。

## 每条必须检查

1. 检查原片选区、首尾及相邻画面，并读取实际 ASR 时间证据。
   台词与实际画面分开陈述；无 ASR 不编造对白或精确时间。
2. 根据原需求与实际画面扩写，不套固定镜头模板。
   核对变化、保留项、遮挡、可用空间和连续动作状态。
   已有合适参考图直接使用；关键帧只支持确实缺失的视觉状态。
3. 播放完整视频及选区前后。变化可见、语义和相关事件与原声一致；
   `modify` 首尾接上且动作不重复，`replace` 新镜头实际成立。
4. 全片解码、尺寸/时长、原音轨哈希和选区外内容检查。
   像素相似度不能替代视觉验收；ASR 不能证明精确口型或音乐节拍。
5. 同需求换模型仍使用原片、原区间和原意图，不以失败成片作为输入。
   修订前检查失败结果，不能只用同义词重试或降低需求。

## 本轮发现并修复的通用问题

- 意图与首尾策略分离：相机变化不再自动解除 `modify` 首尾锁；
  工具要求显式意图，后端拒绝冲突的旧首尾覆盖参数。
- 已知时间区间先检查选区，避免视频 Skill 额外执行整片分析。
- 同需求换模型复用原片，而不是当前 GUI 或最近生成结果。
- 生成画幅由原视频实际尺寸推导，避免无视频参考的竖屏替换生成横屏。
- Context 编辑按实际视频帧数拟合，避免供应商较长音频尾部导致画面少帧、
  选区外内容提前。原音轨仍从原片复制。
- 扩写检查实际空白区域与遮挡，并区分需要可核对的视觉状态和普通文本描述。
- 参考图生成后 DualWriter 已上传、Agent 内存却仍为 data URL 时，视频工具
  从当前项目时间线重新读取持久化图片地址；原生中间帧也拒绝视频封面。
- 如果用户指定的待修改属性存在于原首尾，H3 `modify` 可使用已检查的
  源片首尾修正参考：保持对应构图、身份、姿态与动作，只修正指定属性。
  默认仍用原首尾；此控制不用于整段替换，也不强制每条生成参考图。

- 生成控制直接向 Agent 返回源片对应帧和生成帧，双向核对目标变化及保留属性，
  避免只检查新图而忽略构图、动作、对象位置的漂移。
- 检查工具允许额外选择最多八个源片时间点，保留原首尾/邻接采样，
  用于短暂事件与控制时刻的核对，避免稀疏采样把短事件误判为不存在。
- H3 内容类中间控制保留原视频动作参考；换机位、换场景或修正冲突边界时
  才去掉竞争视频。元数据输入时长和提示词绑定同步遵循实际输入。
