# 视频编辑能力梳理：统一到「局部编辑」

2026-10-08。基于 `codex/video-retake` 当前代码梳理；用户已同意收敛方案。已移除旧截帧编辑入口及默认片段修复中的独立裁剪/生成/二次拼回流程；保留截图定位和外部 API 兼容。

## 名称与产品合同

面向用户使用「局部编辑」（繁中「局部編輯」、日文「部分編集」、英文「Edit segment」）。说明：选择一段视频，描述要改变的内容，其他部分保持不变。按钮、选区状态与聊天上下文使用同一名称。保留内部 `inspect_retake` / `retake_video`、CLI `video retake` 与 MCP `makaron_retake_video` 名称，兼容已有调用。

当前支持选择 0.1–15 秒，源视频最长 120 秒、最高 60 fps；默认 FAL H3 Max，可选 Seedance 2.5。先理解所选画面与前后动作，再扩写需求，生成后拼回完整视频，保留原声与总时长。这里的“保持不变”指选区外内容不改；完整视频重新编码不承诺字节一致。LTX 不在支持模型中。

生成状态按用户更正保持原样，本次不调整模型状态显示。

| 口播精剪、找高光、长片拆短片 | 保留语义选片及剪辑流程 | 需要理解全片、转录与剪辑；局部编辑可作为单个镜头的修补步骤。 |

## 自然语言入口

- GUI、Web 聊天和 CLI 是同一 Agent 工具路径；选区只提供可选时间上下文，不是提交编辑的前提。
- “把 @1 的18–21秒改成多机位”：明确范围，先 inspect_retake，再生成。
- “把 @1 的前半段改成分层效果”：读取实际时长，计算前半段；若超过15秒不能擅自缩短，应使用整片/长视频编辑路由。
- “把 @1 的最后三秒改成夜景”：读取时长，从结尾倒推范围。
- “机器人起跳那段改成侧拍”：先分析和查看帧，定位动作区间；多个起跳片段匹配时才追问。
- “删除最后三秒”“加字幕”“配音”“延长结尾”：同样直接用聊天，但执行对应精确剪辑、字幕、声音或延长工具。
- 相对时间以可见片段为基准，提交工具前换算到原片时间；避免外部截取视频的 source offset 丢失。
- `.1–15s` 是一次局部替换的长度，不是必须从第 `.1` 秒开始，也不要求从零起算。

## 时长与 Seedance 成本呈现

整体默认保留 FAL H3 Max；聊天指定 Seedance 2.5 时优先选 `seedance-2.5-eco`，原生模型仅显式选择。局部编辑的 Eco 使用裁出的参考片段，自动生成并放大，再拼回完整成片。详情卡分别显示编辑区间、生成片段、完整视频和视频输入时长；卡片打开后跟随 live snapshot 更新状态。历史任务可通过原收据刷新元数据，无需再次生成。

截图案例实际编辑 12.3–26s，参考输入和计费均为 13.7s，完整成片为 30.14s。短选区可能为模型最低时长扩展参考上下文（Seedance 通常 4s，H3 通常 5s），但替换区间不会扩大。

## 图片融入片尾的真实路由修复

用户案例“把@1加到@2里去，可以是最后出logo的地方，衔接要自然好玩”被误判成 Remotion 叠图，用户明确要求视频编辑后又遇到尾帧检查失败。诊断确认：

- 路由把泛化的图片/Logo 加入理解成固定叠图，并自行添加可编辑时间轴要求。现在默认将场景内、片尾自然融合走局部编辑；显式固定图层和确定性文字排版仍走 composition。
- 原视频 snapshot 被附加 design_path；preview_frame 按 media_index 查原视频时却读取了该合成。现在显式 media_index 清除上次合成上下文，并优先检查 type=video 的实际 video_meta.videoUrl。显式 design_path 仍具有最高优先级。
- Vercel 只有 FFmpeg，没有 FFprobe，容器时长包括音轨尾部，末帧不存在。现在无 FFprobe 时按压缩视频包计数，保留真实视频帧数；取帧落在空尾时仅解码最后两秒并读取真实末帧。
- 局部编辑增加最多六张创意参考图，独立于源视频、首尾帧与中间机位帧；时间线编号在输入边界映射到供应商编号，图片真实进入模型，缺失参考图时在计费前拒绝。参考图参与任务去重与收据身份，避免同收据换图重提。

本轮回归覆盖原视频/旧合成并存、云端缺少 FFprobe、参考图在 H3/Seedance/Eco 中传递、计费前拒绝未绑定图片和相同收据换图。图片文字的生成保真度仍需实际产物验收，路由和输入合同通过不等同于该视频语义效果通过。
