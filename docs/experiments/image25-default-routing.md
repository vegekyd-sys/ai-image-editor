# Image 2.5 替代 Nano Banana 默认路由：初步研究

日期：2026-09-10。状态：生产已发布 Image 2 → Flare 的替换；本文只研究普通自动生图的下一阶段，未改生产默认、未实现审核失败后的自动换模型。

## 当前事实

- 生产 `IMAGE_MODEL=gemini-3.1-flash-image-preview`，普通自动生图实际为 OpenRouter → Google AI Studio。Flare 使用 FAL / low。Tips 小预览另有 Lite 模型，不能与主图片默认混为一谈。
- 当前 router 对 Image 2.5 为严格单模型；共享 editImage 对该模型仅尝试一次。显式选择、自动默认、透明合同尚未用独立的路由来源字段区分。
- FAL 返回 `detail[].type=content_policy_violation` 时能被后端识别，但包装成普通 `FalImage25RequestError` 后只留下文字；上层不能可靠区分审核、参数、计费、网络和未知付费结果。错误分类需要保留结构化字段，不能依靠匹配自然语言错误句子。
- 4 个历史 Flare 拒绝样本的客户端耗时：15.350、16.013、17.151、17.493 秒，中位数 16.582 秒。对同一 request id 只读重新取得状态，FAL `metrics.inference_time` 分别约 12.439、13.748、12.843、13.108 秒。大部分等待在供应商处理阶段，不能仅通过减少 1.5 秒轮询间隔消除。
- 这些拒绝请求的 queue status 也为 `COMPLETED`，随后 result 返回 422；因此 COMPLETED 只代表任务终态，不代表媒体生成成功。错误中的 `loc=[body,prompt]` 不足以证明只有文本被拒，不能推断图片安全或将全部拒绝称作误杀。
- 官方错误说明要求按 `type` 分支，`content_policy_violation` 是不可重试的 422；该信号不是可随意重试的网络错误。来源：[FAL Model Errors](https://fal.ai/docs/documentation/model-apis/errors)。FAL Image 2.5 输入 schema 公开质量/尺寸等参数，没有公开的 moderation 参数：[Flare edit schema](https://fal.ai/models/openai/gpt-image-2.5/flare/edit/api)。

## 本次额外对照

固定相同中文 brief、来源素材与请求比例；Gemini 保持当前 minimal reasoning，Flare 为 low。模型输出尺寸均约 1MP，但不完全相同，不能称为逐像素同参数基准。每个模型/场景只提交一次，未自动重试或因拒绝改写 prompt。

| 场景 | Gemini 完整调用 | Flare 完整调用 | 成图检查 |
| --- | ---: | ---: | --- |
| 普通人像换公园背景 | 10.155 秒 | 21.863 秒 | 两者均已保存和目视检查，面容、衣服、姿态保持，背景替换完成 |
| 高山湖泊生成 | 不计入 | 19.339 秒 | Flare 成图已查看；Gemini HTTP 200 后本地响应读取失败，未取得可验收图片 |
| 产品换木桌背景 | 不计入 | 28.660 秒 | Flare 成图已查看；Gemini HTTP 200 后本地响应读取失败，未取得可验收图片 |
| 街角咖啡馆生成 | 14.214 秒 | 不计入完整调用 | FAL 原始图已从同一请求只读恢复；两张成图均查看 |
| 产品换石材背景 | 14.697 秒 | 不计入完整调用 | FAL 原始图已从同一请求只读恢复；两张成图均查看 |

后两组 FAL 的本地测试 wrapper 曾把媒体二进制当文本解码；生产实现没有该 wrapper。原始供应商 PNG 完好，已使用 GET 恢复，未重新生成。其初始测量到错误的时间为 42.424 / 23.664 秒，但不纳入完整成功调用速度；原始记录与恢复记录分开保留。前两组 Gemini 的本地读取失败也不能归为模型审核失败。这个小样本只能提供线索，不能报告稳定的均值、P95 或全场景胜率。

同一普通人像的有效对照显示 Flare 在该样本更慢。结合上一批 Flare 13 场景 16.7–33.1 秒的记录，目前没有证据说全量替换会与当前 Gemini 一样快。

## 失败后路由与速度

理论串行耗时：`FAL 返回明确拒绝 + 内容是否允许处理的判定 + 备用模型 + 保存/交付`。

用已测值估算：历史拒绝 15.35–17.49 秒，加本次 Gemini 人像 10.16 秒，是 25.51–27.65 秒；加之前街拍 Gemini 13.27 秒，是 28.62–30.76 秒。两者都还没有包含新增判定、调度、最终保存和 Agent 完整交付开销。这是拼接已有独立测量的估算，不是已实现 fallback 的实测。

要让拒绝后的整体体验接近直接 Gemini 的 10–15 秒，必须在发起 Flare 前选对模型，或付出并行生成的额外成本；单纯串行 fallback 消除不了先等拒绝的时间。默认不建议所有请求双发：会增加付费调用，且不能绕过真正的内容限制。

## 建议实现边界（尚未实施）

1. 把 `routingOrigin=explicit|auto|capability` 和 `failure.kind/status/stage/requestId/retryable/outcomeKnown` 保留到共享图片编排层。队列失败、结果失败、下载失败分别处理。
2. 已知是正常且允许处理的内容、供应商误拒且备用模型也允许时，才讨论 Auto 模式的一次备用调用。真正违规的内容终止；不能把所有审核拒绝无条件交给另一模型，也不降低审核或改写内容规避过滤。具体误拒判定机制仍需确定。
3. 明确指定 Image 2.5 的用户保持显式模型合同；透明 PNG 仍要求真实 alpha，不把不支持透明的 Gemini 当等价备用。参考图数量、比例和编辑语义也要兼容。
4. 对允许的备用情况，在同一次后端工具调用里直接调度，不先把错误送回 Agent 再让其思考下一步。最多一次备用，禁止递归进入 Gemini → Qwen 等现有多级链，UI/消息展示实际模型。
5. 已提交但超时/结果未知的付费请求继续查询同一 request id，下载失败只重取已有输出；不要因为慢就发第二个付费请求。审核、参数错误、缺价格等各自终止或按明确合同处理。
6. 备用调用前按实际 Gemini 价格检查/预留额度；实际模型、供应商成本、最终用户扣费分别记录，不沿用 Flare 的报价。不能把缺失失败计费信息当成免费。
7. 添加 `requestedModel/actualModel/failureKind` 与阶段时间：应用准备、供应商价格查询、提交、排队/运行、结果判定、备用、下载、保存、最终回复。先在独立环境验证，再讨论放量。

建议下一轮验证正常人物/产品/风景/多图/文字布局，保留固定提示词和输入，至少每组 5 次成功样本。对异常路径用确定性的供应商响应回放证明只路由一次、未知结果不双发、违规/显式/透明不换模；真实误拒样本需要先确认允许处理，不重复撞审核。

暂定验收目标供讨论：普通生成图片调用 P95 ≤35 秒、允许备用的完整图片工具 P95 ≤45 秒、完整 Agent 交付 P95 ≤60 秒，并与当前 Gemini 同组样本对比。这里只是建议阈值，不是用户已确认要求或已达到的结论。

产物：worktree `.artifacts/image25/default-comparison/` 的 JSON、原图、恢复记录、拒绝请求阶段数据和图集。生产默认保持 Gemini，未部署本文所述备用路由。
