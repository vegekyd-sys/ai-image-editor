# 默认视频模型切换为 Kling 4.0 Flash（2026-11-09）

分支 `claude/default-model-selection-e18b51`，基线 dev `70e1eef3`。用户决策：默认视频模型由 FAL H3 Max 改为 Kling 4.0 Flash。

## 评测依据

- 场景：线上近 30 天外部用户的 301 条视频生成（排除管理员/测试号）。其中 226 条为 9:16，134 条为 15s；主力是 B2B 工厂/产品外贸短视频（多图参考 + 印尼语/西语口播），约 20% 带参考视频。
- 方法：按类别抽 12 条真实需求，用同一英文提示词（台词保留原语言）和同一参考素材，每个模型各跑一次。用户本人盲评两轮，字母和位置做了平衡。
- 第一轮（H3 Max / Wan 3.0 / Omni 1.2）：Wan 平均名次 1.42，Omni 1.80，H3 Max 2.58。
- 第二轮（加入 Kling 4.0 Flash，前三个模型复用第一轮的成片）：

| | Kling 4.0 Flash | Omni 1.2 | Wan 3.0 | H3 Max |
|---|---|---|---|---|
| 平均名次（越小越好） | **1.92** | 2.10 | 2.25 | 3.42 |
| 第 1 名 | 6/12 | 4/10 | 1/12 | 1/12 |
| 到供应商 URL 的时间（中位 / 最大） | 64s / 134s | 73s / 220s | 234s / 512s | 19s / 56s |
| 价格（$/s） | 0.094 | 0.070 | 0.060 | 0.080 |

- 第二轮中，旧三款之间的两两先后有 30/32 组与第一轮一致。Kling 两两对比胜 Wan 9/12、胜 H3 9/12，与 Omni 5/10 打平。Kling 在空镜运镜和源视频局部修改两类场景排最后。
- 限制：只有一位评审，样本 12 条。Kling 有 4 条因提示词超过 2500 字符，用压缩后的提示词补跑，与其他模型的输入不完全相同。
- 复跑脚本在 `scripts/video-default-ab/`（gitignored）：select → prepare → run.mts → build-review → server → score / score-r2。

## 改动

- 默认模型：`DEFAULT_MODEL_ID = 'kling-4-flash'`（720p，3–20s）。不指定模型时，非 NSFW 的 21–30s 请求走 Seedance 2.5，需要 1080p 的请求走 Kling 4.0，NSFW 仍走 Wan 3.0 Prime，复刻仍走 Wan 3.0 Prime。
- Kling 引用映射（修复）：时间线素材共用 `<<<media_N>>>` 编号，Kling 却把图片和视频分成两组输入。原实现把所有 `media_N` 都改写成 `image_N`，导致引用时间线视频时报“引用了不存在的输入”或指错素材。新增 `prepareKling4References`，分别映射到 `<<<image_N>>>` 和 `<<<video_N>>>`。没被引用的视频：生成时作为运动/风格参考追加说明，编辑时前缀为 `Edit <<<video_N>>>:`。
- 画面比例：EvoLink Kling 省略 `aspect_ratio` 时默认 16:9。现在未指定比例、有参考图、且不是编辑时，按第一张参考图选 Kling 支持比例中最接近的一个；读不到图片时仍为 16:9。
- 提示词长度：Kling 4 系列能力表新增 `maxPromptCharacters: 2500`。video-harness 在计费前拦截超长提示词，并给出“压缩一次、保留镜头、台词和标记、同一模型”的修复提示。线上真实提示词约 18% 超过 2500 字符；Agent 提示词同时加了长度预算。
- 参考视频：Kling 要求参考视频每边 ≥720px。线上用过视频参考的项目中约 4%（540×1170 上传）不达标。现在 Agent 链路会在校验前用 ffmpeg 把短边放大到 720，保持比例；放大后长边超过 2160 的不处理，交给原有校验报错。
- 文案与入口：Agent/legacy 提示词、工具和 MCP 描述、模型选择器（四语，Flash 排在视频第一位）、Flash 生成时间提示（约 1–2 分钟）、Skill（wan-3-0、seedance-2-5）、CLI 默认值，以及 CLI 不指定模型且 `--duration` 超过 20 时自动用 seedance-2.5，并在本地拦截 2500 字符以上的脚本（版本 0.17.16）。
- 合同：core-prompt 修订记录（core-21、core-37、Kling 当前合同替换、animate.md 哈希），skill 路由证据重新预检 3/3，未执行任何媒体生成。
- 未改：Retake 默认仍是 Kling 4.0；multi-angle-video 等 Skill 的自带模型偏好不变；H3 Max 的大图预检（未检查 5760px 上限）另行处理。

## 验收（2026-11-09，本地 3120 端口 + 本分支代码 + 共享数据库，CLI chat 走 Agent，Agent 模型 deepseek-flash）

| 场景 | 请求 | 结果 |
|---|---|---|
| A | 竖版人像照片 + 15s 多镜头女装口播，不指定模型/比例，直接提交 | `kling-4-flash`，脚本 636 字符，`<<<image_1>>>` 映射正确；720×1280、15.04s、有音轨，人物服装一致、五个镜头按序；282 credits（= 15 × $0.094 × 2）；已转存 cdn.makaron.app。项目 `2fa8c9e4-924d-4d71-98b6-1ab5fae72c66` |

| B5 | 540×960 上传视频作光线/色调参考，指定 Kling 4.0 Flash | 参考视频自动放大 540×960 → 720×1280（8.3s）；`<<<media_1>>>` 映射为视频输入；720×1280、8.04s、有音轨；202 credits（=(8+8) × $0.063 × 2）。项目 `2b80a62e-3450-44d1-b77f-0a297ccbcf0d` |

验收中发现并已修复：

- 第一次 B（改裙子颜色）：Agent 看到提示词里“Kling 每边 ≥720px”，主动换成 SeeDance 2.0。已在提示词里注明“时间线视频低于 720px 会自动放大，不要因此换模型”。
- B3：放大后仍被“参考视频短于 3 秒”拦下。根因是 Agent 链路传给校验的参考视频信息缺少 `durationSec`，缺失的时长被当成 0。这是 Kling 4 系列上线以来，Agent 引用时间线视频一直被拒的旧 bug。现在会带上快照时长，校验也只拦截已测得、确实短于 3 秒的片段。

另外两次属于设计内的路由，不是缺陷：

- B2：整段改色走了 Retake。Retake 默认仍是 Kling 4.0，有自己的尺寸检查（不经过新的自动放大），被拒后 Agent 改用 Seedance 2.5 Eco。改动前就是这样。
- B4：“参考镜头节奏，换人物和衣服”被识别为复刻，按复刻规则默认 Wan 3.0 Prime。

验收合计花费约 2,170 credits，其中 B、B2、B3、B4 是排查路由时多花的。图形界面未在本地登录检查：模型选择器排序、默认选中和生成时间提示只有单测和 i18n 检查覆盖。

## 遗留

- H3 Max 大图预检没有检查 5760px 上限。
- CLI 0.17.16 需要在合入 dev 并上线后，按 release 流程发 npm。
